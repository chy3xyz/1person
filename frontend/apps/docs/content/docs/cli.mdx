The 1Person CLI mirrors almost everything the Web UI can do (create [issues](/issues), assign [agents](/agents), start the [daemon](/daemon-runtimes), and more). This page lists every top-level command with a one-line description. For the full set of flags and examples, run `1person <command> --help`.

## Getting authenticated

Run this the first time you use the CLI to obtain a **personal access token (PAT)**:

```bash
1person login
```

Your browser opens automatically. After you approve in the web app, the CLI saves the PAT (prefixed with `1p_`) to `~/.config/1person/config.json`. Every subsequent command authenticates with that PAT.

<Callout type="tip">
For CI or headless environments, skip the browser flow: create a PAT in the web app under **Settings → Personal Access Tokens**, then run `1person login --token <1p_...>` to supply it directly.
</Callout>

For the difference between token types, see [Authentication and tokens](/auth-tokens).

## Auth and setup

| Command | Purpose |
|---|---|
| `1person login` | Log in and save a PAT |
| `1person auth status` | Show current login status, user, and workspace |
| `1person auth logout` | Clear the local PAT |
| `1person setup cloud` | One-shot setup for 1Person Cloud (login + install daemon) |
| `1person setup self-host` | One-shot setup for a self-hosted backend |

## Workspaces and members

| Command | Purpose |
|---|---|
| `1person workspace list` | List every workspace you can access |
| `1person workspace get <slug>` | Show details for one workspace |
| `1person workspace member list` | List members of the current workspace |
| `1person workspace update <id> --name "..." [--description "..."] [--context "..."] [--issue-prefix "..."]` | Update workspace metadata (admin/owner). Long fields accept `--description-stdin` / `--context-stdin`. |

## Issues and projects

<Callout type="info">
`list` commands (`1person issue list`, `autopilot list`, `project list`, etc.) print short, copy-paste-ready IDs by default — issue keys like `MUL-123` for issues, short UUID prefixes for the rest. The `<id>` argument on the follow-up commands below accepts either the short ID or the full UUID, so the typical flow is `1person issue list` → copy the key → `1person issue get MUL-123`. Pass `--full-id` to a list command when you need the canonical UUID.
</Callout>

| Command | Purpose |
|---|---|
| `1person issue list` | List issues (prints copy-paste-ready issue keys) |
| `1person issue get <id>` | Show a single issue (accepts an issue key or a UUID) |
| `1person issue create --title "..."` | Create a new issue |
| `1person issue update <id> ...` | Update an issue (status, priority, assignee, etc.) |
| `1person issue assign <id> --agent <slug>` | Assign to an agent (triggers a task immediately) |
| `1person issue status <id> --set <status>` | Shortcut to change status |
| `1person issue search <query>` | Keyword search |
| `1person issue runs <id>` | Show agent runs on an issue |
| `1person issue rerun <id>` | Re-enqueue a fresh task for the issue's current agent assignee |
| `1person issue comment <id> ...` | Nested: view / post comments |
| `1person issue subscriber <id> ...` | Nested: subscribe / unsubscribe |
| `1person project list/get/create/update/delete/status` | Project CRUD |

### Skill import conflicts

`1person skill import --url <url>` defaults to `--on-conflict fail`. If a skill
with the same name already exists, the command exits with a structured
`conflict` result and does not change the workspace.

Use `--on-conflict overwrite` when you created the existing skill and want to
replace its content while preserving its ID and agent bindings. Use
`--on-conflict rename` to import a copy with an automatic suffix such as `-2`.
Use `--on-conflict skip` to leave the existing skill untouched and report
`skipped`.

```bash
1person skill import --url https://skills.sh/acme/repo/review-helper
1person skill import --url https://skills.sh/acme/repo/review-helper --on-conflict overwrite
1person skill import --url https://skills.sh/acme/repo/review-helper --on-conflict rename
1person skill import --url https://skills.sh/acme/repo/review-helper --on-conflict skip
```

## Squads

| Command | Purpose |
|---|---|
| `1person squad list` | List squads in the workspace |
| `1person squad get <id>` | Show a single squad |
| `1person squad create --name "..." --leader <agent>` | Create a squad (owner / admin) |
| `1person squad update <id> ...` | Update name, description, instructions, leader, or avatar |
| `1person squad delete <id>` | Archive (soft-delete) — transfers assigned issues to the leader |
| `1person squad member list/add/remove/set-role <squad-id>` | Manage squad members and update roles in place |
| `1person squad activity <issue-id> <action\|no_action\|failed> --reason "..."` | Used by squad leader agents to record an evaluation per turn |

See [Squads](/squads) for the full model.

## Daemon and runtimes

| Command | Purpose |
|---|---|
| `1person daemon start` | Start the daemon (background by default; add `--foreground` to run in the foreground) |
| `1person daemon stop` | Stop the daemon |
| `1person daemon restart` | Restart the daemon |
| `1person daemon status` | Check whether the daemon is online and its concurrency |
| `1person daemon logs` | View daemon logs |
| `1person runtime list` | List runtimes in the current workspace |
| `1person runtime usage` | Show resource usage |
| `1person runtime activity` | Recent activity log |
| `1person runtime update <id> ...` | Update a runtime's configuration |

| Command | Purpose |
|---|---|

| `1person config` | View or edit local CLI configuration |
| `1person version` | Print the CLI version |
| `1person update` | Upgrade the CLI to the latest release |
