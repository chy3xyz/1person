1Person における**ランタイム**とは、あなたのマシンのデーモンと、デーモンが見つけた AI コーディングツール 1 つが組になったものです。オンボーディングの「ランタイムを接続」ステップで **No supported tools detected** と表示される場合、それはデーモンがマシンをスキャンしたものの、駆動方法を知っている 5 個のツールのいずれも見つけられなかったことを意味します。以下のツールのいずれかをインストールしてから、そのステップに戻って再スキャンしてください — 数秒以内にランタイムが表示されます。

このページは次のドキュメントのインストール側の補完ドキュメントです。

- [デーモンとランタイム](/daemon-runtimes) — 検出の仕組み
- [AI コーディングツールマトリクス](/providers) — 各ツールができることとできないこと（セッション再開、MCP、モデル選択）

<Callout type="info">
1Person サーバーがあなたの API キーやツール自体を見ることは決してありません。以下のすべて — インストール、認証、モデルアクセス — はあなたのローカルマシン上に存在します。何かが失敗する場合、それはほぼ常にローカルの問題です。
</Callout>

## 始める前に

以下の**すべての**ツールに 2 つの前提条件が適用されます。

1. **1Person デーモンが実行中である必要があります。** [1Person CLI](/cli) をインストールした後に `1person daemon start` を実行するか、デーモンを自動的に起動する [1Person デスクトップアプリ](/desktop-app)を使用してください。デーモンが実行されていなければ、ツールを検出する主体がありません。
2. **ツールに到達できる必要があります。** デーモンは各ツールを名前で呼び出して実行します（各セクションの**デーモンが探す名前**の列を参照）。`PATH` がふつうの場所ですが、DeepSeek Harness と Pi の 2 つは自分のホームディレクトリにインストールされ、デーモンもそこを探します。シンボリックリンクは必要ありません。ターミナルで `which <name>` で見つからなければ、デーモンも見つけられません。インストール後は、新しいターミナルを開く（またはデーモンを再起動する）ことで、新しい `PATH` エントリが反映されるようにしてください。

ツールをインストールした後は、デーモンを再起動してください。

```bash
1person daemon restart
```

または、デスクトップアプリではアプリを再起動するだけで構いません。デーモンは起動のたびに再スキャンします。

## デーモンが動かせる 5 つのツール

おおよそ利用者の多い順に並べています。すでに認証情報を持っているものを選んで使ってください — 5 種すべてをインストールする必要はありません。

### OpenCode (SST)

オープンソースの CLI エージェントで、デーモンの既定の選択肢です: 有償のサブスクリプションなしで答えられます。自身の構成ファイルから利用可能なモデルを動的に発見します — 自分のモデルカタログを持ち込みたい人に最適です。daemon はエージェントのモデルを `--model` として渡し、セッションの再開は行わず、MCP 構成も引き継ぎません。

| | |
|---|---|
| デーモンが探す名前 | `opencode` |
| インストール | [opencode.ai](https://opencode.ai/) の公式ガイド、または GitHub リポジトリ [github.com/sst/opencode](https://github.com/sst/opencode) に従ってください。一般的な方法はインストールスクリプトまたは npm パッケージです。 |
| 認証 | OpenCode のドキュメントに従ってモデルプロバイダー（Anthropic、OpenAI など）を構成してください。 |

### Claude Code (Anthropic)

非対話の素の形で動かします: プロンプトを 1 つ渡して答えを受け取ります。CLI 自体はセッション再開、MCP 構成、`--max-turns` のような細かな調整フラグに対応していますが、daemon はいまいずれも渡しません。

| | |
|---|---|
| デーモンが探す名前 | `claude` |
| インストール | [claude.com/claude-code](https://www.claude.com/claude-code) の公式ガイドに従ってください。標準的な方法は npm パッケージ `@anthropic-ai/claude-code` です（Node.js 18+ が必要）。 |
| 認証 | `claude` を一度実行して CLI 内のログイン手順に従うか、`ANTHROPIC_API_KEY` を設定してください。 |

### Codex (OpenAI)

承認ゲートがよりきめ細かい JSON-RPC 2.0 のトランスポートです。daemon は読み取り専用サンドボックス付きの `codex exec` として実行するので、答えるだけのタスクはディスクに触れません。モデルには CLI 自身のデフォルトが使われます。

| | |
|---|---|
| デーモンが探す名前 | `codex` |
| インストール | [github.com/openai/codex](https://github.com/openai/codex) の公式ガイドに従ってください。標準的な方法は npm パッケージ `@openai/codex` です。 |
| 認証 | `codex login`（ブラウザベース）または `OPENAI_API_KEY`。 |

### DeepSeek Harness (DeepSeek)

プラグインを土台としたエージェントハーネスです。daemon は **headless プロファイル**経由で動かします: タスクを 1 つ渡すと答えが stdout に出てプロセスが終了します。この CLI は `PATH` ではなく `$DSH_HOME`（デフォルトは `~/.dsh`）にインストールされ、daemon もそこを探します。

| | |
|---|---|
| デーモンが探す名前 | `dsh` — `PATH` 上、または `$DSH_HOME/profiles/node_modules/@deepseek-ai/dsh/lib/bin.js` |
| インストール | DeepSeek Harness のリポジトリ [github.com/deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) を参照してください。 |
| 認証 | DeepSeek の API キー（`DEEPSEEK_API_KEY`）が必要で、ハーネス自身の資格情報サービスで構成します。 |

### Pi (Inflection AI)

ミニマルです。daemon は非対話モード（`pi -p`）経由で動かします: プロンプトが処理され、答えが stdout に戻ってプロセスが終了します。この CLI はランチャーを `PATH` ではなく `$PI_CODING_AGENT_DIR`（デフォルトは `~/.pi/agent`）にインストールされ、daemon もそこを探します。

| | |
|---|---|
| デーモンが探す名前 | `pi` — `PATH` 上、または `$PI_CODING_AGENT_DIR/bin/pi` |
| インストール | Inflection の CLI ドキュメント [pi.ai](https://pi.ai/) を参照してください。 |
| 認証 | ベンダーのドキュメントに従います。 |

## ラインアップ済みだが、まだ動かせないツール

この 8 個は 1Person のツールラインアップに含まれますが、daemon にはコードパスがありません: 検出も実行もせず、対応が実装されるまでインストールしても何も変わりません。インストールと認証のメモを置いているのは、対応が実装されたあともこのページが 1 つの行き先として使えるようにするためです。

### Cursor (Anysphere)

Cursor エディターに対応する CLI です。

| | |
|---|---|
| デーモンが探す名前 | `cursor-agent` — まだ未対応 |
| インストール | [Cursor エディタ](https://cursor.com/)をインストールしてから、[docs.cursor.com](https://docs.cursor.com/) のドキュメントに従って CLI をインストールしてください。バイナリ名は `cursor` ではなく `cursor-agent` です。 |
| 認証 | Cursor エディタを通じてログインすると、CLI がそのセッションを再利用します。 |

### GitHub Copilot

モデルのルーティングはあなたの GitHub アカウントのエンタイトルメント（entitlement）を通じて行われます — ツールが自分でモデルを選ぶのではなく、どのモデルを受け取るかは GitHub が決めます。

| | |
|---|---|
| デーモンが探す名前 | `copilot` — まだ未対応 |
| インストール | GitHub の CLI ドキュメント [github.com/github/copilot-cli](https://github.com/github/copilot-cli) を参照してください。 |
| 認証 | CLI を通じたブラウザベースの GitHub ログイン。 |
| 備考 | ログインしているアカウントに有効な GitHub Copilot サブスクリプションが必要です。 |

### Gemini (Google)

Gemini 2.5 および 3 シリーズに対応しています。

| | |
|---|---|
| デーモンが探す名前 | `gemini` — まだ未対応 |
| インストール | [github.com/google-gemini/gemini-cli](https://github.com/google-gemini/gemini-cli) の公式ガイドに従ってください。標準的な方法は npm パッケージ `@google/gemini-cli` です。 |
| 認証 | `gemini` を実行すると Google アカウントのログインを求められるか、`GEMINI_API_KEY` を設定してください。 |

### Kiro CLI (Amazon)

ACP-over-stdio のトランスポートです。

| | |
|---|---|
| デーモンが探す名前 | `kiro-cli` — まだ未対応 |
| インストール | [kiro.dev](https://kiro.dev/) の Kiro ドキュメントを参照してください。バイナリ名は `kiro` ではなく `kiro-cli` です。 |
| 認証 | AWS アカウントベースで、Kiro 独自のオンボーディングに従ってください。 |

### Kimi (Moonshot)

ACP プロトコルのエージェントで、主に中国市場を対象としています。

| | |
|---|---|
| デーモンが探す名前 | `kimi` — まだ未対応 |
| インストール | [github.com/MoonshotAI/kimi-cli](https://github.com/MoonshotAI/kimi-cli) の公式ガイドに従ってください。 |
| 認証 | Moonshot API キーで、ベンダーのドキュメントに従って構成します。 |

### Hermes (Nous Research)

ACP プロトコルのエージェントです（Kimi とトランスポートを共有）。

| | |
|---|---|
| デーモンが探す名前 | `hermes` — まだ未対応 |
| インストール | 最新の CLI ディストリビューションは Nous Research のリポジトリ [github.com/NousResearch](https://github.com/NousResearch) を参照してください。 |
| 認証 | ベンダーのドキュメントに従います。 |

### OpenClaw

オープンソースの CLI エージェントオーケストレーターです。**モデルはエージェント層にバインドされます**（`openclaw agents add --model`）— タスクごとに上書きすることはできません。

| | |
|---|---|
| デーモンが探す名前 | `openclaw` — まだ未対応 |
| インストール | プロジェクト [github.com/openclaw-org/openclaw](https://github.com/openclaw-org/openclaw) を参照してください（コミュニティによる保守）。 |
| 認証 | OpenClaw のドキュメントに従って、基盤となるモデルプロバイダーを構成してください。 |

### Antigravity (Google)

Google の Antigravity CLI（`agy`）です。Google の Antigravity サービスと組になり、Gemini ベースのモデルを実行します。

| | |
|---|---|
| デーモンが探す名前 | `agy` — まだ未対応 |
| インストール | [antigravity.google/docs/cli-overview](https://antigravity.google/docs/cli-overview) の公式ガイドに従ってください。CLI はあらかじめビルドされて提供されます — `agy install` を一度実行して PATH とシェルエイリアスを設定してください。 |
| 認証 | `agy` を対話的に一度実行して Google アカウントのログインを完了するか、Antigravity デスクトップアプリを通じてログインしてください — CLI は GUI が書き込んだ keyring エントリを再利用します。 |

## インストールした後

1. **バイナリに到達できることを確認してください。** 新しいターミナルを開いて `which <name>`（例: `which claude`、`which opencode`、`which dsh`、`which pi`）を実行してください。パスが出力されれば、デーモンが見つけます — `dsh` と `pi` については `PATH` のエントリがなくても見つけます。何も出力されない場合は、まずシェルの `PATH` を修正してください（典型的な原因は、リロードされていないシェルごとの rc ファイルです）。
2. **デーモンを再起動してください。** `1person daemon restart` を実行するか、デスクトップアプリを再起動してください。デーモンは起動時にのみスキャンします。
3. **ランタイムページを確認してください。** 1Person UI の**ランタイム**ページに、デーモンが選んだツールのランタイムが表示されるはずです。行に「offline」と表示される場合は、[デーモンとランタイム → ランタイムがオフラインと表示されるとき](/daemon-runtimes#ランタイムがオフラインと表示される時点)を参照してください。
4. **オンボーディングに戻ってください。** 「ランタイムを接続」ステップはポーリングを行い、数秒以内に新しいランタイムを認識します — リロードは不要です。

## トラブルシューティング

- **`which` はバイナリを見つけるのにデーモンは見つけません。** デーモンが古い `PATH` で起動されています。再起動してください。
- **別のツールが選ばれてしまいました。** デーモンは固定された順序で、実行できるもののうち最初のものを選びます。`ONEPERSON_AGENT_PROVIDER` に使いたいツールの名前を指定し、デーモンを再起動してください。
- **バイナリは存在するのに起動に失敗します。** ターミナルからツール自体の `--version` や `--help` を一度実行してください — ここで発生する失敗のほとんどは、認証の欠落、期限切れのトークン、または Node.js / ランタイムの不一致です。
- **ランタイムページに行は表示されるのに、タスクがすぐに失敗します。** タスクをトリガーしながら `1person daemon logs -f` を確認してください。デーモンはツール自体のエラー出力をそのまま表示します。

より広範な症状については、[トラブルシューティングガイド](/troubleshooting)を参照してください。
