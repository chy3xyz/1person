1Person CLI 把 Web UI 能做的事几乎全部搬到了命令行上（创建 [issue](/issues)、分配 [智能体](/agents)、启动 [守护进程](/daemon-runtimes) 等等）。这一页把所有顶级命令列出来，每条配一句用途。完整 flag 和示例用 `1person <命令> --help` 查。

## 认证入口

第一次用 CLI 时先登录，拿一个**个人访问令牌（Personal Access Token，PAT）**：

```bash
1person login
```

浏览器会自动打开，你在 Web 端同意后，CLI 把 PAT（`1p_` 前缀）保存到 `~/.config/1person/config.json`。此后所有命令都会自动用这个 PAT 认证。

<Callout type="tip">
CI / 无浏览器环境跳过浏览器流程：先在 Web 端 **Settings → Personal Access Tokens** 创建一个 PAT，然后 `1person login --token <1p_...>` 直接填入。
</Callout>

Token 类型的详细区分见 [认证与令牌](/auth-tokens)。

## 认证与初始化

| 命令 | 用途 |
|---|---|
| `1person login` | 登录并保存 PAT |
| `1person auth status` | 查看当前登录状态、用户、工作区 |
| `1person auth logout` | 清除本地 PAT |
| `1person setup cloud` | 1Person Cloud 一键初始化（登录 + 装 daemon） |
| `1person setup self-host` | 自部署后端的一键初始化 |

## 工作区和成员

| 命令 | 用途 |
|---|---|
| `1person workspace list` | 列出你有权访问的所有工作区 |
| `1person workspace get <slug>` | 查看一个工作区的详情 |
| `1person workspace member list` | 列出当前工作区的成员 |
| `1person workspace update <id> --name "..." [--description "..."] [--context "..."] [--issue-prefix "..."]` | 修改 workspace 元数据（admin/owner 权限）。长文本可用 `--description-stdin` / `--context-stdin`。 |

## Issue 和 Project

<Callout type="info">
`list` 类命令（`1person issue list`、`autopilot list`、`project list` 等）表格里默认显示**可直接复制**的短 ID：issue 是 key（如 `MUL-123`），其余资源是 UUID 短前缀。下面表格里的 `<id>` 同时接受短 ID 和完整 UUID，所以典型用法是 `1person issue list` → 复制 key → `1person issue get MUL-123`。需要完整 UUID 时给 `list` 加 `--full-id`。
</Callout>

| 命令 | 用途 |
|---|---|
| `1person issue list` | 列出 issue（默认显示可复制的 issue key） |
| `1person issue get <id>` | 查看单条 issue（接受 issue key 或 UUID） |
| `1person issue create --title "..."` | 创建新 issue |
| `1person issue update <id> ...` | 修改 issue（状态、优先级、分配人等） |
| `1person issue assign <id> --agent <slug>` | 分配给智能体（立即触发任务） |
| `1person issue status <id> --set <status>` | 快捷改状态 |
| `1person issue search <query>` | 关键字搜索 |
| `1person issue runs <id>` | 查看 issue 上智能体跑过的任务 |
| `1person issue rerun <id>` | 给该 issue 当前的智能体分配人重新创建一条任务 |
| `1person issue comment <id> ...` | 嵌套：看 / 发评论 |
| `1person issue subscriber <id> ...` | 嵌套：订阅 / 取消订阅 |
| `1person project list/get/create/update/delete/status` | Project CRUD |

### Skill 导入冲突

`1person skill import --url <url>` 默认等同于 `--on-conflict fail`。如果工作区里已经有同名 Skill，命令会返回结构化 `conflict` 结果并退出，不会修改工作区。

如果你是已有 Skill 的 creator，并且想用新导入内容覆盖它，同时保留原 Skill 的 ID 和 agent 绑定，用 `--on-conflict overwrite`。如果想保留已有 Skill、另存一份，用 `--on-conflict rename`，系统会自动加 `-2` 这类后缀。如果只是批量导入时遇到同名项就跳过，用 `--on-conflict skip`。

```bash
1person skill import --url https://skills.sh/acme/repo/review-helper
1person skill import --url https://skills.sh/acme/repo/review-helper --on-conflict overwrite
1person skill import --url https://skills.sh/acme/repo/review-helper --on-conflict rename
1person skill import --url https://skills.sh/acme/repo/review-helper --on-conflict skip
```

## 小队

| 命令 | 用途 |
|---|---|
| `1person squad list` | 列出工作区里的小队 |
| `1person squad get <id>` | 查看一个小队 |
| `1person squad create --name "..." --leader <agent>` | 创建小队（owner / admin）|
| `1person squad update <id> ...` | 修改名字、描述、instructions、队长、头像 |
| `1person squad delete <id>` | 归档（软删除）—— 同时把分配给小队的 issue 转给队长 |
| `1person squad member list/add/remove/set-role <squad-id>` | 管理小队成员并原地更新 role |
| `1person squad activity <issue-id> <action\|no_action\|failed> --reason "..."` | 队长智能体每轮结束时调用，记录 evaluation |

完整模型见 [小队](/squads)。

## 守护进程和运行时

| 命令 | 用途 |
|---|---|
| `1person daemon start` | 启动 daemon（默认后台；加 `--foreground` 前台跑）|
| `1person daemon stop` | 停止 daemon |
| `1person daemon restart` | 重启 daemon |
| `1person daemon status` | 查看 daemon 是否在线 + 并发情况 |
| `1person daemon logs` | 查看 daemon 日志 |
| `1person runtime list` | 列出当前工作区的 runtime |
| `1person runtime usage` | 查看资源使用情况 |
| `1person runtime activity` | 近期活动记录 |
| `1person runtime update <id> ...` | 更新 runtime 配置 |

## 查完整 flag

每条命令都支持 `--help`：

```bash
1person issue create --help
1person agent update --help
```

v2 会给每条命令一个独立的详细 reference 页。
