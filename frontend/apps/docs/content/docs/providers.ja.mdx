1Person は **13 個の AI コーディングツール**をサポートしています。いずれも同じインターフェース（キューへの投入、ディスパッチ、実行、結果の返却）を実装しているため、同じ 1Person ボードからどれでも動かすことができます。**しかし機能の詳細は大きく異なります**: セッション再開が実際に動作するか、MCP がサポートされるか、スキルファイルがどこに置かれるか、モデルをどう選択するか。このページが完全な対応表です。

<Callout type="warning">
ローカル daemon が動かせるのは、現時点でこのうち **5 個**です: **OpenCode、Claude Code、Codex、DeepSeek Harness、Pi**。残りの 8 個にはコードパスがありません — 検出も実行もせず、そのツールのために登録されたランタイムはタスクを実行できません。以下の各行がどちらに当たるかを示し、機能の列は CLI が原理上できるかどうかではなく、daemon が実際に何をするかを記しています。
</Callout>

エージェントを作成するときにツールを選ぶ際のガイダンスは、[エージェントの作成と構成](/agents-create)を参照してください。

## 各ツールの用途

### Antigravity

Google が提供します。CLI バイナリ名は `agy` です。Google の Antigravity サービスと連携し、Gemini ベースのデフォルトモデルが付属しています。CLI は会話を再開でき（`--conversation <id>`）、モデルカタログも列挙できます（`agy models`）。**ローカル daemon には agy のコードパスがありません** — 検出も実行もしないので、いま 1Person からその機能に到達することはできません。

### Claude Code

Anthropic が提供します。CLI はセッション再開、MCP 構成の読み取り、`--max-turns` や `--append-system-prompt` のような細かな調整フラグに対応しており、Anthropic API キーが必要です。**ローカル daemon はこれを動かします** — ただの非対話形式で、プロンプトを 1 つ渡して答えを受け取ります。daemon はセッション id を渡さず、MCP 構成も引き継ぎません。

### Codex

OpenAI が提供します。JSON-RPC 2.0 を使い、ステートフルな能力がより強く、よりきめ細かい承認メカニズム（`exec_command` と `patch_apply` に対する手動承認）を備えています。**ローカル daemon はこれを動かします** — 読み取り専用サンドボックス付きの `codex exec` として実行するので、答えるだけのタスクはディスクに触れません。モデルには CLI 自身のデフォルトが使われます。

### Copilot

GitHub が提供します。モデルルーティングは GitHub アカウントのエンタイトルメントを経由します — ツールが自分でモデルを選ぶのではなく、GitHub がどのモデルを与えるかを決めます。**ローカル daemon には現在このツールのコードパスがありません。**

### Cursor

Anysphere が提供し、Cursor エディターに対応する CLI です。CLI はヘッドレスで実行でき、`.cursor/mcp.json` から MCP 構成を読み取ります。**ローカル daemon には現在このツールのコードパスがありません。**

### Gemini

Google が提供し、Gemini 2.5 および 3 シリーズに対応しています。**ローカル daemon には現在このツールのコードパスがありません。**

### Hermes

Nous Research が提供します。ACP プロトコルを使用します（Kimi とトランスポートを共有）。**ローカル daemon には現在このツールのコードパスがありません。**

### Kimi

Moonshot が提供し、中国市場を対象としています。Hermes と ACP プロトコルを共有します。**ローカル daemon には現在このツールのコードパスがありません。**

### Kiro CLI

Amazon が提供します。`kiro-cli acp` を通じて stdio 上で ACP を使用します。**ローカル daemon には現在このツールのコードパスがありません。**

### OpenCode

SST が提供するオープンソースです。自身の構成ファイルから利用可能なモデルと model variant を動的に発見します — 自分のモデルカタログを持ち込みたい人に最適です。**ローカル daemon はこれを動かします** — しかも既定の選択肢で、有償のサブスクリプションなしで答えられます。daemon は自分のエージェントプロファイルをタスクの作業ディレクトリに書き出し（答えるだけのタスクにはツールが一切渡されません）、エージェントのモデルを `--model` として渡し、CLI はプライベートサーバーに対して実行して、タスクの隣にあるプロファイルが適用されるようにしています。セッションの再開は行わず、MCP 構成も引き継ぎません。

### OpenClaw

オープンソースプロジェクトで、CLI エージェントのオーケストレーターです。構成は厳格に制御されています: ユーザーは `--model` や `--system-prompt` を渡せず、エージェント登録時の構成が決定します。**ローカル daemon には現在このツールのコードパスがありません。**

### DeepSeek Harness

DeepSeek が提供し、DeepSeek Harness が土台です。**ローカル daemon はこれを動かします** — headless プロファイル経由で、タスクを 1 つ渡すと答えが stdout に出てプロセスが終了します。タスクは毎回ゼロから始まります — CLI 自体は `--session-id` でセッションを再開できますが、daemon はそれを使いません — モデルにはプロファイル既定のものが使われます。この CLI は `PATH` ではなく自分のホームディレクトリ（`~/.dsh`）にインストールされるので、daemon はそちらを見ます。

### Pi

Inflection AI が提供し、ミニマルです。**ローカル daemon はこれを動かします** — 非対話モード（`pi -p`）経由で、プロンプトが処理され、答えが stdout に戻ってプロセスが終了します。daemon はセッションファイルを書かないので、タスクは毎回ゼロから始まります。この CLI はランチャーを `PATH` ではなく `~/.pi/agent` にインストールするので、daemon はそちらも探します。

## セッション再開: まだ配線されていません

セッション再開の仕組みは[タスク](/tasks#タスクが以前のコンテキストから続行できるか)で扱います。以下は**正確な現在の状態**です。

| 状態 | ツール | 意味 |
|---|---|---|
| ❌ 未実装 | 13 個すべて | daemon は CLI にセッション id を渡さないため、すべてのタスクはクリーンなコンテキストから始まります |

**判断のために**: タスクをまたいでエージェントにコンテキストを保持させたいワークフロー（失敗時のリトライ、手動での再実行、対話的な反復）は、いまのところどの CLI からも得られません。[チャット](/chat)は別の方法でコンテキストを保持します — サーバーが会話履歴をプロンプトに埋め込むので、エージェントはセッションを再開するのではなく履歴を読みます。

## MCP 構成: 受け付けられるが、渡されない

**ローカル daemon で `mcp_config` を消費するツールはありません。** このフィールドはエージェントに保存され、タスクと一緒に daemon まで届きますが、daemon はそれをどの CLI にも渡しません — 設定した MCP サーバーは、どのツールでも効果を持たず、エラーも警告も出ません。

これを機能させるには、ツールごとに固有の経路が要ります（Claude Code は `--mcp-config` と `--strict-mcp-config`、Codex は `$CODEX_HOME/config.toml` の `mcp_servers` ブロック、ACP 系は `mcpServers`）。いま、どれも配線されていません。

<Callout type="warning">
今日エージェントに `mcp_config` を設定しても、MCP サーバーは**エージェントに届きません**。警告は出ません — 構成は CLI に向かう途中でそのまま捨てられます。
</Callout>

## スキルファイルが置かれる場所

各ツールは**それぞれの**スキル探索パスを使います。次の表は各 CLI がスキルを読み込む場所 — ツール自身が文書化しているパスです。

| ツール | パス | ネイティブ探索か |
|---|---|---|
| Claude Code | `.claude/skills/` | ✅ ネイティブ |
| Codex | `$CODEX_HOME/skills/` | ✅ ネイティブ |
| Copilot | `.github/skills/` | ✅ ネイティブ |
| Cursor | `.cursor/skills/` | ✅ ネイティブ |
| Kimi | `.kimi/skills/` | ✅ ネイティブ |
| Kiro CLI | `.kiro/skills/` | ✅ ネイティブ |
| OpenCode | `.opencode/skills/` | ✅ ネイティブ |
| Pi | `.pi/skills/` | ✅ ネイティブ |
| Antigravity | `.agents/skills/` | ✅ ネイティブ（Gemini CLI のワークスペースレイアウトを継承 — [Antigravity ドキュメント](https://antigravity.google/docs/gcli-migration)を参照） |
| Gemini | `.agent_context/skills/` | ⚠️ 汎用フォールバック |
| Hermes | `.agent_context/skills/` | ⚠️ 汎用フォールバック |
| OpenClaw | `.agent_context/skills/` | ⚠️ 汎用フォールバック |

**daemon はスキルファイルをタスクのワークスペースにコピーしていません。** ローカルのスキルディレクトリをスキャンして、サーバーにプレースホルダーの一覧を返すだけなので、UI 上ではアタッチ済みに見えるスキルが、CLI に実際に渡されるとは限りません。

スキルの作成と使用については、[スキル](/skills)を参照してください。
