1Person에서 **런타임**이란 여러분의 기기에 있는 데몬과, 데몬이 찾아낸 AI 코딩 도구 하나가 짝을 이룬 것입니다. 온보딩의 "런타임 연결" 단계에서 **지원되는 도구를 감지하지 못했습니다**라고 표시된다면, 데몬이 여러분의 기기를 훑어보았는데 구동 방법을 아는 다섯 개의 도구를 하나도 찾지 못했다는 뜻입니다. 아래 도구 중 하나를 설치한 다음 해당 단계로 돌아와 다시 스캔하세요. 몇 초 안에 런타임이 나타납니다.

이 페이지는 다음 문서의 설치 측면 동반 문서입니다.

- [데몬과 런타임](/daemon-runtimes) — 감지가 작동하는 방식
- [AI 코딩 도구 대조표](/providers) — 각 도구가 할 수 있는 것과 할 수 없는 것(세션 재개, MCP, 모델 선택)

<Callout type="info">
1Person 서버는 여러분의 API 키나 도구 자체를 결코 보지 못합니다. 아래의 모든 것 — 설치, 인증, 모델 접근 — 은 여러분의 로컬 기기에 존재합니다. 무언가 실패한다면 거의 항상 로컬 문제입니다.
</Callout>

## 시작하기 전에

아래 **모든** 도구에 두 가지 사전 조건이 적용됩니다.

1. **1Person 데몬이 실행 중이어야 합니다.** [1Person CLI](/cli)를 설치한 후 `1person daemon start`를 실행하거나, 데몬을 자동으로 시작하는 [1Person 데스크톱 앱](/desktop-app)을 사용하세요. 데몬이 실행 중이지 않으면 도구를 감지할 주체가 없습니다.
2. **도구에 접근할 수 있어야 합니다.** 데몬은 각 도구를 이름으로 호출해 실행합니다(각 섹션의 **데몬이 찾는 이름** 열 참고). 보통은 `PATH`가 그 자리입니다. DeepSeek Harness와 Pi는 둘 다 `PATH`가 아니라 자신의 홈 디렉터리에 설치하고, 데몬은 그곳도 찾기 때문에 심볼릭 링크를 만들 필요가 없습니다. 터미널에서 `which <name>`으로 찾을 수 없다면 데몬도 찾지 못합니다. 설치한 뒤에는 새 터미널을 열거나(또는 데몬을 재시작하여) 새 `PATH` 항목이 반영되도록 하세요.

도구를 설치한 후에는 데몬을 재시작하세요.

```bash
1person daemon restart
```

또는 데스크톱 앱에서는 앱을 다시 실행하기만 하면 됩니다. 데몬은 시작될 때마다 다시 스캔합니다.

## 데몬이 구동할 수 있는 다섯 가지 도구

많이 쓰이는 순서대로 대략 나열했습니다. 이미 자격 증명을 갖고 있는 것을 골라 사용하세요. 다섯 개를 모두 설치할 필요는 없습니다.

### OpenCode (SST)

오픈소스 CLI 에이전트이며, 데몬의 기본 선택지입니다: 유료 구독 없이도 답할 수 있습니다. 자체 구성 파일에서 사용 가능한 모델을 동적으로 발견합니다 — 자신의 모델 카탈로그를 직접 가져오려는 사용자에게 잘 맞습니다. 데몬은 에이전트의 모델을 `--model`로 전달하며, 세션은 재개하지 않고 MCP 구성도 전달하지 않습니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `opencode` |
| 설치 | [opencode.ai](https://opencode.ai/)의 공식 가이드 또는 GitHub 저장소 [github.com/sst/opencode](https://github.com/sst/opencode)를 따르세요. 일반적인 방법은 설치 스크립트 또는 npm 패키지입니다. |
| 인증 | OpenCode의 문서에 따라 모델 제공자(Anthropic, OpenAI 등)를 구성하세요. |

### Claude Code (Anthropic)

평범한 비대화형 형태로 구동합니다 — 프롬프트 하나를 넣으면 답이 나옵니다. CLI 자체는 세션 재개와 MCP 구성, `--max-turns` 같은 세부 조정 플래그를 지원하지만, 데몬은 현재 그 어떤 것도 넘겨주지 않습니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `claude` |
| 설치 | [claude.com/claude-code](https://www.claude.com/claude-code)의 공식 가이드를 따르세요. 일반적인 방법은 npm 패키지 `@anthropic-ai/claude-code`입니다(Node.js 18+ 필요). |
| 인증 | `claude`를 한 번 실행하고 CLI 내 로그인 절차를 따르거나, `ANTHROPIC_API_KEY`를 설정하세요. |

### Codex (OpenAI)

더 세분화된 승인 게이트를 갖춘 JSON-RPC 2.0 전송 방식입니다. 데몬은 읽기 전용 샌드박스와 함께 `codex exec`로 실행하므로, 답만 하는 작업은 디스크를 건드리지 않습니다. CLI 자체의 기본 모델이 사용됩니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `codex` |
| 설치 | [github.com/openai/codex](https://github.com/openai/codex)의 공식 가이드를 따르세요. 일반적인 방법은 npm 패키지 `@openai/codex`입니다. |
| 인증 | `codex login`(브라우저 기반) 또는 `OPENAI_API_KEY`. |

### DeepSeek Harness (DeepSeek)

플러그인 위에 만든 에이전트 하네스입니다. 데몬은 그 **headless 프로파일**로 구동합니다: 작업을 하나 넘기면 답이 stdout으로 나오고 프로세스가 종료됩니다. 이 CLI는 `PATH`가 아니라 `$DSH_HOME`(기본값 `~/.dsh`) 아래에 설치되고, 데몬은 그곳도 찾습니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `dsh` — `PATH`에 있거나 `$DSH_HOME/profiles/node_modules/@deepseek-ai/dsh/lib/bin.js` |
| 설치 | DeepSeek Harness 저장소 [github.com/deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)를 참고하세요. |
| 인증 | DeepSeek API 키(`DEEPSEEK_API_KEY`)가 필요하며, 하네스 자체의 자격 증명 서비스로 구성합니다. |

### Pi (Inflection AI)

미니멀합니다. 데몬은 비대화형 모드(`pi -p`)로 구동합니다: 프롬프트를 처리하면 답이 stdout으로 돌아오고 프로세스가 종료됩니다. 이 CLI는 `PATH`가 아니라 `$PI_CODING_AGENT_DIR`(기본값 `~/.pi/agent`) 아래에 런처를 설치하고, 데몬은 그곳도 찾습니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `pi` — `PATH`에 있거나 `$PI_CODING_AGENT_DIR/bin/pi` |
| 설치 | Inflection의 CLI 문서 [pi.ai](https://pi.ai/)를 참고하세요. |
| 인증 | 공급사 문서에 따릅니다. |

## 명단에 있지만 아직 구동할 수 없는 도구

아래 여덟 개는 1Person의 도구 명단에 포함되어 있지만, 데몬에는 이들을 위한 코드 경로가 없습니다: 감지도 하지 않고 실행하지도 않으므로, 지금 설치해도 지원이 실제로 구현되기 전까지는 달라지는 것이 없습니다. 설치와 인증 메모를 여기에 둔 이유는, 지원이 시작되는 시점에 이 페이지가 확인할 곳 하나를 유지하기 위해서입니다.

### Cursor (Anysphere)

Cursor 에디터에 대응하는 CLI입니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `cursor-agent` — 아직 지원되지 않음 |
| 설치 | [Cursor 에디터](https://cursor.com/)를 설치한 다음 [docs.cursor.com](https://docs.cursor.com/)의 문서에 따라 CLI를 설치하세요. 바이너리 이름은 `cursor`가 아니라 `cursor-agent`입니다. |
| 인증 | Cursor 에디터를 통해 로그인하면 CLI가 해당 세션을 재사용합니다. |

### GitHub Copilot

모델 라우팅은 GitHub 계정 권한을 거칩니다 — 도구가 직접 모델을 고르지 않고, 어떤 모델을 받을지는 GitHub가 결정합니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `copilot` — 아직 지원되지 않음 |
| 설치 | GitHub의 CLI 문서 [github.com/github/copilot-cli](https://github.com/github/copilot-cli)를 참고하세요. |
| 인증 | CLI를 통한 브라우저 기반 GitHub 로그인. |
| 비고 | 로그인한 계정에 활성화된 GitHub Copilot 구독이 필요합니다. |

### Gemini (Google)

Gemini 2.5 및 3 시리즈를 지원합니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `gemini` — 아직 지원되지 않음 |
| 설치 | [github.com/google-gemini/gemini-cli](https://github.com/google-gemini/gemini-cli)의 공식 가이드를 따르세요. 일반적인 방법은 npm 패키지 `@google/gemini-cli`입니다. |
| 인증 | `gemini`를 실행하면 Google 계정 로그인을 요청하거나, `GEMINI_API_KEY`를 설정하세요. |

### Kiro CLI (Amazon)

stdio 위에서 동작하는 ACP 전송 방식입니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `kiro-cli` — 아직 지원되지 않음 |
| 설치 | [kiro.dev](https://kiro.dev/)의 Kiro 문서를 참고하세요. 바이너리 이름은 `kiro`가 아니라 `kiro-cli`입니다. |
| 인증 | AWS 계정 기반이며, Kiro 자체 온보딩을 따르세요. |

### Kimi (Moonshot)

ACP 프로토콜 에이전트로, 주로 중국 시장을 겨냥합니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `kimi` — 아직 지원되지 않음 |
| 설치 | [github.com/MoonshotAI/kimi-cli](https://github.com/MoonshotAI/kimi-cli)의 공식 가이드를 따르세요. |
| 인증 | Moonshot API 키이며, 공급사 문서에 따라 구성합니다. |

### Hermes (Nous Research)

ACP 프로토콜 에이전트입니다(Kimi와 전송 방식을 공유).

| | |
|---|---|
| 데몬이 찾는 이름 | `hermes` — 아직 지원되지 않음 |
| 설치 | 최신 CLI 배포본은 Nous Research의 저장소 [github.com/NousResearch](https://github.com/NousResearch)를 참고하세요. |
| 인증 | 공급사 문서에 따릅니다. |

### OpenClaw

오픈소스 CLI 에이전트 오케스트레이터입니다. **모델은 에이전트 계층에 바인딩됩니다**(`openclaw agents add --model`) — 작업별로 재정의할 수 없습니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `openclaw` — 아직 지원되지 않음 |
| 설치 | 프로젝트 [github.com/openclaw-org/openclaw](https://github.com/openclaw-org/openclaw)를 참고하세요(커뮤니티 유지 관리). |
| 인증 | OpenClaw의 문서에 따라 기반 모델 제공자를 구성하세요. |

### Antigravity (Google)

Google의 Antigravity CLI(`agy`)입니다. Google의 Antigravity 서비스와 짝을 이루며 Gemini 기반 모델을 실행합니다.

| | |
|---|---|
| 데몬이 찾는 이름 | `agy` — 아직 지원되지 않음 |
| 설치 | [antigravity.google/docs/cli-overview](https://antigravity.google/docs/cli-overview)의 공식 가이드를 따르세요. CLI는 미리 빌드되어 제공됩니다 — `agy install`을 한 번 실행하여 PATH와 셸 별칭을 설정하세요. |
| 인증 | `agy`를 대화형으로 한 번 실행하여 Google 계정 로그인을 완료하거나, Antigravity 데스크톱 앱을 통해 로그인하세요 — CLI는 GUI가 기록한 keyring 항목을 재사용합니다. |

## 설치한 후에

1. **바이너리에 접근할 수 있는지 확인하세요.** 새 터미널을 열고 `which <name>`(예: `which claude`, `which opencode`, `which dsh`, `which pi`)을 실행하세요. 경로가 출력되면 데몬이 찾을 수 있습니다 — `dsh`와 `pi`는 `PATH` 항목이 없어도 데몬이 찾습니다. 아무것도 출력되지 않으면 먼저 셸의 `PATH`를 수정하세요(전형적인 원인은 다시 로드되지 않은 셸별 rc 파일입니다).
2. **데몬을 재시작하세요.** `1person daemon restart`를 실행하거나 데스크톱 앱을 다시 실행하세요. 데몬은 시작할 때만 스캔합니다.
3. **런타임 페이지를 확인하세요.** 1Person UI의 **런타임** 페이지에 데몬이 선택한 도구의 런타임이 이제 표시되어야 합니다. 행에 "offline"이라고 표시되면 [데몬과 런타임 → 런타임이 오프라인으로 표시되는 시점](/daemon-runtimes#런타임이-오프라인으로-표시되는-시점)을 참고하세요.
4. **온보딩으로 돌아가세요.** "런타임 연결" 단계는 폴링을 수행하며 몇 초 안에 새 런타임을 인식합니다 — 새로 고칠 필요가 없습니다.

## 문제 해결

- **`which`는 바이너리를 찾는데 데몬은 찾지 못합니다.** 데몬이 예전 `PATH`로 시작되었습니다. 재시작하세요.
- **다른 도구가 선택되었습니다.** 데몬은 정해진 순서대로 자신이 구동할 수 있는 첫 번째 도구를 고릅니다. 원하는 도구를 직접 지정하려면 `ONEPERSON_AGENT_PROVIDER`를 설정하고 데몬을 재시작하세요.
- **바이너리는 존재하지만 실행에 실패합니다.** 터미널에서 도구 자체의 `--version`이나 `--help`를 한 번 실행하세요 — 여기서 발생하는 대부분의 실패는 인증 누락, 만료된 토큰, 또는 Node.js / 런타임 불일치입니다.
- **런타임 페이지에 행은 표시되지만 작업이 즉시 실패합니다.** 작업을 트리거하면서 `1person daemon logs -f`를 확인하세요. 데몬은 도구 자체의 오류 출력을 그대로 보여줍니다.

더 광범위한 증상은 [문제 해결 가이드](/troubleshooting)를 참고하세요.
