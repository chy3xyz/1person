1Person는 **13개의 AI 코딩 도구**를 기본 지원합니다. 이들은 모두 동일한 인터페이스(대기열 적재, 디스패치, 실행, 결과 반환)를 구현하므로, 같은 1Person 보드에서 어느 것이든 구동할 수 있습니다. **하지만 기능 세부사항은 크게 다릅니다**: 세션 재개가 실제로 동작하는지, MCP를 지원하는지, 스킬 파일이 어디에 위치하는지, 모델을 어떻게 선택하는지. 이 페이지가 전체 대조표입니다.

<Callout type="warning">
로컬 데몬은 현재 이 중 **다섯 개**만 구동합니다: **OpenCode, Claude Code, Codex, DeepSeek Harness, Pi**. 나머지 여덟 개에는 코드 경로가 없습니다 — 감지도 하지 않고, 그 도구용으로 등록된 런타임은 작업을 실행하지도 못합니다. 아래 표의 각 행이 어느 쪽인지 보여주며, 기능 열은 CLI가 원래 할 수 있는 일이 아니라 데몬이 실제로 하는 일을 담았습니다.
</Callout>

에이전트를 생성할 때 도구를 고르는 방법은 [에이전트 생성 및 구성](/agents-create)을 참고하세요.

## 각 도구의 용도

### Antigravity

Google에서 제공합니다. CLI 바이너리 이름은 `agy`입니다. Google의 Antigravity 서비스와 짝을 이루며 Gemini 기반 기본 모델을 함께 제공합니다. CLI 자체는 대화를 재개할 수 있고(`--conversation <id>`) 모델 카탈로그를 나열할 수도 있습니다(`agy models`). **로컬 데몬에는 agy를 위한 코드 경로가 없습니다** — 감지하지도, 실행하지도 않으므로 1Person에서는 위 기능 중 어느 것도 사용할 수 없습니다.

### Claude Code

Anthropic에서 제공합니다. CLI는 세션 재개와 MCP 구성 읽기를 지원하고, `--max-turns`와 `--append-system-prompt` 같은 세부 조정 플래그를 받습니다. Anthropic API 키가 필요합니다. **로컬 데몬이 구동합니다** — 평범한 비대화형 형태로, 프롬프트 하나를 넣으면 답이 나옵니다. 데몬은 세션 id를 넘기지 않고 MCP 구성도 전달하지 않습니다.

### Codex

OpenAI에서 제공합니다. JSON-RPC 2.0을 사용하고, 상태 유지 능력이 더 강하며, 더 세밀한 승인 메커니즘(`exec_command` 및 `patch_apply`에 대한 수동 승인)을 갖추고 있습니다. **로컬 데몬이 구동합니다** — 읽기 전용 샌드박스와 함께 `codex exec`로 실행하므로, 답만 하는 작업은 디스크를 건드리지 않습니다. CLI 자체의 기본 모델이 사용됩니다.

### Copilot

GitHub에서 제공합니다. 모델 라우팅은 GitHub 계정 권한을 거칩니다 — 도구가 직접 모델을 고르지 않고, 어떤 모델을 받을지는 GitHub가 결정합니다. **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### Cursor

Anysphere에서 제공하며, Cursor 에디터에 대응하는 CLI입니다. CLI는 헤드리스로 구동할 수 있고 `.cursor/mcp.json`에서 MCP 구성을 읽습니다. **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### Gemini

Google에서 제공하며, Gemini 2.5 및 3 시리즈를 지원합니다. **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### Hermes

Nous Research에서 제공합니다. ACP 프로토콜을 사용합니다(Kimi와 전송 계층을 공유합니다). **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### Kimi

Moonshot에서 제공하며, 중국 시장을 겨냥합니다. Hermes와 ACP 프로토콜을 공유합니다. **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### Kiro CLI

Amazon에서 제공합니다. `kiro-cli acp`를 통해 stdio 위에서 ACP를 사용합니다. **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### OpenCode

SST에서 제공하는 오픈소스입니다. 자체 구성 파일에서 사용 가능한 모델과 모델 variant를 동적으로 발견합니다 — 자신의 모델 카탈로그를 직접 가져오려는 사용자에게 잘 맞습니다. **로컬 데몬이 구동하며**, 기본 선택지이기도 합니다: 유료 구독 없이도 답할 수 있기 때문입니다. 데몬은 작업 디렉터리에 자체 에이전트 프로필을 기록하고(답만 하는 작업에는 아예 도구가 부여되지 않습니다), 에이전트의 모델을 `--model`로 전달하며, CLI를 자체 서버에 붙여 실행하므로 작업 옆에 놓인 프로필이 그대로 적용됩니다. 세션은 재개하지 않고 MCP 구성도 전달하지 않습니다.

### OpenClaw

오픈소스 프로젝트이며, CLI 에이전트 오케스트레이터입니다. 구성이 엄격하게 통제됩니다: 사용자는 `--model`이나 `--system-prompt`를 전달할 수 없으며, 에이전트 등록 구성이 결정합니다. **현재 로컬 데몬에는 이 도구를 위한 코드 경로가 없습니다.**

### DeepSeek Harness

DeepSeek에서 제공하며 DeepSeek Harness를 기반으로 합니다. **로컬 데몬이 구동합니다** — headless 프로파일로, 작업을 하나 넘기면 답이 stdout으로 나오고 프로세스가 종료됩니다. 모든 작업은 새로 시작합니다 — CLI 자체는 `--session-id`로 세션을 재개할 수 있지만 데몬은 그것을 쓰지 않습니다 — 그리고 프로필 자체의 기본 모델이 사용됩니다. 이 CLI는 `PATH`가 아니라 자신의 홈 디렉터리(`~/.dsh`)에 설치되므로 데몬이 그곳을 찾습니다.

### Pi

Inflection AI에서 제공하며, 미니멀합니다. **로컬 데몬이 구동합니다** — 비대화형 모드(`pi -p`)로, 프롬프트를 처리하면 답이 stdout으로 돌아오고 프로세스가 종료됩니다. 데몬은 세션 파일을 쓰지 않으므로 모든 작업은 새로 시작합니다. 이 CLI는 `PATH`가 아니라 `~/.pi/agent`에 런처를 설치합니다. 데몬은 그곳도 찾습니다.

## 세션 재개: 아직 연결되지 않음

세션 재개 메커니즘은 [작업](/tasks#작업이-이전-컨텍스트에서-이어질-수-있는지)에서 다룹니다. 다음은 **정확한 현재 상태**입니다.

| 상태 | 도구 | 의미 |
|---|---|---|
| ❌ 미구현 | 13개 전체 | 데몬이 CLI에 세션 id를 넘기지 않으므로 모든 작업은 깨끗한 컨텍스트에서 시작합니다 |

**의사결정을 위해**: 작업 간에 에이전트가 컨텍스트를 유지해야 하는 워크플로(실패 재시도, 수동 재실행, 대화형 반복)는 현재 어떤 도구에서도 CLI로부터 그 기능을 얻지 못합니다. [채팅](/chat)은 다른 방식으로 컨텍스트를 유지합니다 — 서버가 대화를 프롬프트에 렌더링하므로, 에이전트는 세션을 재개하는 대신 기록을 읽습니다.

## MCP 구성: 받지만 전달되지 않음

**로컬 데몬에서는 어떤 도구도 `mcp_config`를 소비하지 않습니다.** 이 필드는 에이전트에 저장되어 작업과 함께 데몬까지 전달되지만, 데몬은 이를 어떤 CLI에도 넘기지 않습니다 — 그래서 설정해 둔 MCP 서버는 모든 도구에서 아무런 효과가 없으며, 오류도 경고도 없습니다.

이것이 동작하려면 도구마다 별도의 경로가 필요합니다(Claude Code는 `--strict-mcp-config`와 함께 `--mcp-config`를 받고, Codex는 `$CODEX_HOME/config.toml`의 `mcp_servers` 블록을 원하며, ACP 계열은 `mcpServers`를 받습니다). 그런 경로는 아직 하나도 연결되어 있지 않습니다.

<Callout type="warning">
오늘 에이전트에 `mcp_config`를 설정하더라도, MCP 서버는 **에이전트에 전달되지 않습니다**. 경고는 따로 나오지 않습니다 — 구성은 CLI로 가는 길에 그냥 버려집니다.
</Callout>

## 스킬 파일이 위치하는 곳

각 도구는 **자체** 스킬 탐색 경로를 사용합니다. 아래 표는 각 CLI가 스킬을 읽어들이는 위치입니다 — 도구 자체가 문서로 밝힌 경로입니다.

| 도구 | 경로 | 기본 탐색 여부 |
|---|---|---|
| Claude Code | `.claude/skills/` | ✅ 기본 |
| Codex | `$CODEX_HOME/skills/` | ✅ 기본 |
| Copilot | `.github/skills/` | ✅ 기본 |
| Cursor | `.cursor/skills/` | ✅ 기본 |
| Kimi | `.kimi/skills/` | ✅ 기본 |
| Kiro CLI | `.kiro/skills/` | ✅ 기본 |
| OpenCode | `.opencode/skills/` | ✅ 기본 |
| Pi | `.pi/skills/` | ✅ 기본 |
| Antigravity | `.agents/skills/` | ✅ 기본 (Gemini CLI의 워크스페이스 레이아웃을 상속 — [Antigravity 문서](https://antigravity.google/docs/gcli-migration) 참고) |
| Gemini | `.agent_context/skills/` | ⚠️ 범용 fallback |
| Hermes | `.agent_context/skills/` | ⚠️ 범용 fallback |
| OpenClaw | `.agent_context/skills/` | ⚠️ 범용 fallback |

**데몬은 아직 스킬 파일을 작업 워크스페이스로 복사하지 않습니다.** 로컬 스킬 디렉터리를 스캔해 자리표시자 목록만 서버에 보고하므로, UI에서 연결된 것처럼 보이는 스킬이 실제로 CLI에 전달되는 것은 아닐 수 있습니다.

스킬의 생성과 사용은 [스킬](/skills)을 참고하세요.
