The `1person` CLI connects your local machine to 1Person. It handles authentication, workspace management, issue tracking, and runs the agent daemon that executes AI tasks locally.

## Authentication

### Browser Login

```bash
1person login
```

Opens your browser for OAuth authentication, creates a 90-day personal access token, and auto-configures your workspaces.

### Token Login

```bash
1person login --token <1p_...>
```

Authenticate using a personal access token directly. Useful for headless environments. Pass `--token=` with an empty value to be prompted interactively (so the token never lands in shell history).

### Check Status

```bash
1person auth status
```

Shows your current server, user, and token validity.

### Logout

```bash
1person auth logout
```

Removes the stored authentication token.

## Agent Daemon

The daemon is the local agent runtime. It detects available AI CLIs on your machine, registers them with the 1Person server, and executes tasks when agents are assigned work.

### Start

```bash
1person daemon start
```

By default, the daemon runs in the background and logs to `~/.1person/daemon.log`.

To run in the foreground (useful for debugging):

```bash
1person daemon start --foreground
```

### Stop

```bash
1person daemon stop
```

### Status

```bash
1person daemon status
1person daemon status --output json
```

Shows PID, uptime, detected agents, and watched workspaces.

### Logs

```bash
1person daemon logs              # Last 50 lines
1person daemon logs -f           # Follow (tail -f)
1person daemon logs -n 100       # Last 100 lines
```

### Supported Agents

The daemon auto-detects these AI CLIs on your PATH:

| CLI | Command | Description |
|-----|---------|-------------|
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code) | `claude` | Anthropic's coding agent |
| [Codex](https://github.com/openai/codex) | `codex` | OpenAI's coding agent |
| [Gemini CLI](https://github.com/google-gemini/gemini-cli) | `gemini` | Google's coding agent |
| OpenCode | `opencode` | Open-source coding agent |
| OpenClaw | `openclaw` | Open-source coding agent |
| Hermes | `hermes` | Nous Research coding agent |
| Kimi | `kimi` | Moonshot coding agent |
| Kiro CLI | `kiro-cli` | Kiro ACP coding agent |
| Pi | `pi` | Inflection coding agent |
| Cursor Agent | `cursor-agent` | Cursor coding agent |

You need at least one installed. The daemon registers each detected CLI as an available runtime.

### How It Works

1. On start, the daemon detects installed agent CLIs and registers a runtime for each agent in each watched workspace
2. It polls the server at a configurable interval (default: 3s) for claimed tasks
3. When a task arrives, it creates an isolated workspace directory, spawns the agent CLI, and streams results back
4. Heartbeats are sent periodically (default: 15s) so the server knows the daemon is alive
5. On shutdown, all runtimes are deregistered

### Configuration

Daemon behavior is configured via flags or environment variables:

| Setting | Flag | Env Variable | Default |
|---------|------|--------------|---------|
| Poll interval | `--poll-interval` | `ONEPERSON_DAEMON_POLL_INTERVAL` | `3s` |
| Heartbeat interval | `--heartbeat-interval` | `ONEPERSON_DAEMON_HEARTBEAT_INTERVAL` | `15s` |
| Agent timeout | `--agent-timeout` | `ONEPERSON_AGENT_TIMEOUT` | `0`（不限制，由看门狗兜底）|
| Max concurrent tasks | `--max-concurrent-tasks` | `ONEPERSON_DAEMON_MAX_CONCURRENT_TASKS` | `20` |
| Daemon ID | `--daemon-id` | `ONEPERSON_DAEMON_ID` | hostname |
| Device name | `--device-name` | `ONEPERSON_DAEMON_DEVICE_NAME` | hostname |
| Runtime name | `--runtime-name` | `ONEPERSON_AGENT_RUNTIME_NAME` | `Local Agent` |
| Workspaces root | — | `ONEPERSON_WORKSPACES_ROOT` | `~/1person_workspaces` |

### Self-Hosted Server

When connecting to a self-hosted 1Person instance, point the CLI to your server before logging in:

```bash
export ONEPERSON_APP_URL=https://app.example.com
export ONEPERSON_SERVER_URL=wss://api.example.com/ws

1person login
1person daemon start
```

Or set them persistently:

```bash
1person config set app_url https://app.example.com
1person config set server_url wss://api.example.com/ws
```

### Profiles

Profiles let you run multiple daemons on the same machine — for example, one for production and one for a staging server.

```bash
# Set up a staging profile
1person setup self-host --profile staging --server-url https://api-staging.example.com --app-url https://staging.example.com

# Start its daemon
1person daemon start --profile staging

# Default profile runs separately
1person daemon start
```

Each profile gets its own config directory (`~/.1person/profiles/<name>/`), daemon state, health port, and workspace root.

## Workspaces

### List Workspaces

```bash
1person workspace list
```

Watched workspaces are marked with `*`. The daemon only processes tasks for watched workspaces.

### Watch / Unwatch

```bash
1person workspace watch <workspace-id>
1person workspace unwatch <workspace-id>
```

### Get Details

```bash
1person workspace get <workspace-id>
1person workspace get <workspace-id> --output json
```

### List Members

```bash
1person workspace member list <workspace-id>
```

### Update Workspace

需要 admin 或 owner 权限。所有字段都是部分更新（PATCH 语义）：未传的字段保持不变。

```bash
1person workspace update <workspace-id> --name "Acme Eng"
1person workspace update <workspace-id> \
  --description "Engineering team workspace" \
  --issue-prefix ENG
```

长文本走 stdin（保留换行/反斜杠）：

```bash
cat <<'CTX' | 1person workspace update <workspace-id> --context-stdin
我们是一支 5 人 AI-native 团队。
工作语言：中文 + 英文混合。
CTX
```

可编辑字段：`--name`、`--description` / `--description-stdin`、`--context` / `--context-stdin`、`--issue-prefix`。`slug` 创建后只读，不暴露在 CLI。`--description` 与 `--description-stdin`（以及 `context` 同名对）互斥。未传任何字段 flag 时命令拒绝执行，避免空 PATCH 触发无意义的 workspace 更新事件。`--issue-prefix ""` 也会被拒绝：当前后端在 prefix 为空时静默跳过该字段，CLI 在本地拦下避免“看似成功的 no-op”。

## Issues

### List Issues

```bash
1person issue list
1person issue list --status in_progress
1person issue list --priority urgent --assignee "Agent Name"
1person issue list --assignee-id 5fb87ac7-23b5-4a7a-81fa-ed295a54545d
1person issue list --full-id
1person issue list --limit 20 --output json
```

表格输出默认显示可直接复制到后续命令的 issue `KEY`（例如 `MUL-123`）；需要完整 UUID 时使用 `--full-id`。Available filters: `--status`, `--priority`, `--assignee` / `--assignee-id`, `--project`, `--limit`. 在重名 workspace 下用 `--assignee-id <uuid>` 可以精确锁定一个成员或 agent。

### Get Issue

```bash
1person issue get MUL-123
1person issue get <uuid>
1person issue get <id> --output json
```

`<id>` 同时接受 issue key（`1person issue list` 表格里直接显示，例如 `MUL-123`）和完整 UUID（给 `list` 加 `--full-id` 可显示）。同样的规则适用于下面 `update` / `assign` / `status` / `comment` / `subscriber` / `runs` 等接受 `<id>` 的命令。

### Create Issue

```bash
1person issue create --title "Fix login bug" --description "..." --priority high --assignee "Lambda"
1person issue create --title "Fix login bug" --assignee-id 5fb87ac7-23b5-4a7a-81fa-ed295a54545d
```

Flags: `--title` (required), `--description`, `--status`, `--priority`, `--assignee` / `--assignee-id`, `--parent`, `--project`, `--due-date`. 脚本里如果已经拿到了 UUID（例如来自 `1person workspace member list --output json`），传 `--assignee-id <uuid>`（与 `--assignee` 互斥）以精确锁定。

### Update Issue

```bash
1person issue update <id> --title "New title" --priority urgent
```

### Assign Issue

```bash
1person issue assign <id> --to "Lambda"
1person issue assign <id> --to-id 5fb87ac7-23b5-4a7a-81fa-ed295a54545d
1person issue assign <id> --unassign
```

`--to-id <uuid>`（与 `--to` 互斥）按 UUID 精确分配；适合重名 workspace 下脚本化场景。

### Change Status

```bash
1person issue status <id> in_progress
```

Valid statuses: `backlog`, `todo`, `in_progress`, `in_review`, `done`, `blocked`, `cancelled`.

### Comments

```bash
# List comments
1person issue comment list <issue-id>

# Add a comment
1person issue comment add <issue-id> --content "Looks good, merging now"

# Reply to a specific comment
1person issue comment add <issue-id> --parent <comment-id> --content "Thanks!"

# Delete a comment
1person issue comment delete <comment-id>
```

### Execution History

```bash
# List all execution runs for an issue
1person issue runs <issue-id>
1person issue runs <issue-id> --full-id
1person issue runs <issue-id> --output json

# View messages for a specific execution run
1person issue run-messages <task-id>
1person issue run-messages <short-task-id> --issue <issue-id>
1person issue run-messages <task-id> --output json

# Incremental fetch (only messages after a given sequence number)
1person issue run-messages <task-id> --since 42 --output json
```

`runs` 的表格输出默认显示 task UUID 短前缀；需要完整 task UUID 时使用 `--full-id`。`run-messages` 可直接接受完整 task UUID；从 `runs` 表格复制短前缀时需要同时传 `--issue <issue-id>`，CLI 只会在该 issue 的 runs 内解析。

## Projects

Projects group related issues (e.g. a sprint, an epic, a workstream). Every project
belongs to a workspace and can optionally have a lead (member or agent).

### List Projects

```bash
1person project list
1person project list --status in_progress
1person project list --output json
```

Available filters: `--status`.

### Get Project

```bash
1person project get <id>
1person project get <id> --output json
```

### Create Project

```bash
1person project create --title "2026 Week 16 Sprint" --icon "🏃" --lead "Lambda"
```

Flags: `--title` (required), `--description`, `--status`, `--icon`, `--lead`.

### Update Project

```bash
1person project update <id> --title "New title" --status in_progress
1person project update <id> --lead "Lambda"
```

Flags: `--title`, `--description`, `--status`, `--icon`, `--lead`.

### Change Status

```bash
1person project status <id> in_progress
```

Valid statuses: `planned`, `in_progress`, `paused`, `completed`, `cancelled`.

### Delete Project

```bash
1person project delete <id>
```

### Associating Issues with Projects

Use the `--project` flag on `issue create` / `issue update` to attach an issue to a
project, or on `issue list` to filter issues by project:

```bash
1person issue create --title "Login bug" --project <project-id>
1person issue update <issue-id> --project <project-id>
1person issue list --project <project-id>
```

## Configuration

### View Config

```bash
1person config show
```

Shows config file path, server URL, app URL, and default workspace.

### Set Values

```bash
1person config set server_url wss://api.example.com/ws
1person config set app_url https://app.example.com
1person config set workspace_id <workspace-id>
```

## Other Commands

```bash
1person version              # Show CLI version and commit hash
1person update               # Update to latest version
1person agent list           # List agents in the current workspace
```

## Output Formats

Most commands support `--output` with two formats:

- `table` — human-readable table (default for list commands)
- `json` — structured JSON (useful for scripting and automation)

```bash
1person issue list --output json
1person daemon status --output json
```
